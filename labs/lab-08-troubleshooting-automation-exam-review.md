# Lab 08 - Troubleshooting, Automation, and Exam Review

## Objectives

- Practise structured troubleshooting.
- Review controller-based networking.
- Understand JSON and REST API basics.
- Build an exam review checklist.

## Steps

1. Use a trainer-provided broken topology or introduce one controlled fault.
2. Write the symptom and expected behavior.
3. Check physical and interface status.
4. Check IP addressing and gateways.
5. Check VLANs and trunks.
6. Check routing table and next hop.
7. Check ACLs, NAT, DHCP, and other services.
8. Change only one thing at a time.
9. Verify the fix with `ping`, `traceroute`, and relevant `show` commands.
10. Compare traditional networking and controller-based networking.
11. Identify control plane, data plane, northbound API, and southbound API concepts.
12. Read a simple JSON object and identify keys and values.
13. Explain REST methods: GET, POST, PUT/PATCH, DELETE.
14. Create a personal study checklist for weak CCNA topics.

## Validation

- Troubleshooting notes follow a logical path.
- Fault is fixed and verified.
- Automation concepts are explained in plain language.
- Exam checklist is specific.

## Review Questions

1. Why should troubleshooting be structured?
2. What is the difference between control plane and data plane?
3. Why is JSON common in network automation?
4. Which CCNA domain needs the most review for you?
